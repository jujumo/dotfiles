= Dotfiles
:toc:
:toc-placement: preamble

Personal dotfiles managed with https://www.chezmoi.io/[chezmoi].

chezmoi only tracks the dotfiles themselves. All installation (packages, Oh My Zsh, the `jumo` theme, chezmoi itself) lives in a standalone `install.sh` bootstrap script.

== Install

One line, on a fresh machine:

[source,shell]
----
sh -c "$(curl -fsLS https://raw.githubusercontent.com/jujumo/dotfiles/main/install.sh)"
----

This installs base packages, Oh My Zsh and chezmoi, then runs `chezmoi init --apply` to lay down the dotfiles (including the `jumo` theme).

To point at a different source repo, set `DOTFILES_REPO`:

[source,shell]
----
DOTFILES_REPO=git@github.com:you/dotfiles.git \
  sh -c "$(curl -fsLS https://raw.githubusercontent.com/jujumo/dotfiles/main/install.sh)"
----

=== Authorizing SSH login keys

Set `SSH_KEYS_URL` to also authorize SSH keys for logging *into* this machine. The installer fetches the public keys from that URL and appends them to `~/.ssh/authorized_keys` (append-only and idempotent — existing entries are left untouched), and installs `openssh-server` so the host is reachable. Unset by default, so nothing is authorized unless you opt in.

The handiest source is your GitHub account's public keys:

[source,shell]
----
SSH_KEYS_URL=https://github.com/jujumo.keys \
  sh -c "$(curl -fsLS https://raw.githubusercontent.com/jujumo/dotfiles/main/install.sh)"
----

Any URL `curl` can read works (including a local `file://` path). Only *public* keys are ever handled — no private key material is involved.

== What gets installed

The `install.sh` script sets up:

* common CLI tools (`nano`, `git`, `curl`, ...)
* *zsh* and *Oh My Zsh* (unattended, without generating its own `.zshrc` — chezmoi owns that)
* *chezmoi*, into `~/.local/bin`
* *openssh-server* — only when `SSH_KEYS_URL` is set (see above)
* *zellij*, into `~/.local/bin`
* *appman*, into `~/.local/bin`

Files not meant for `$HOME` (`README.adoc`, `CLAUDE.md`, `install.sh`) are excluded via `.chezmoiignore`.

== Update

`install.sh` is idempotent and is also the update command: re-run it and it pulls the latest commits of the source repo and applies them (steps already done — Oh My Zsh, chezmoi — are skipped).

[source,shell]
----
~/.local/share/chezmoi/install.sh
----

Use the `curl` one-liner instead if `install.sh` itself changed (a new package, for example), since the local copy is only refreshed by the *previous* update:

[source,shell]
----
sh -c "$(curl -fsLS https://raw.githubusercontent.com/jujumo/dotfiles/main/install.sh)"
----

For the dotfiles only, without going through the package step:

[source,shell]
----
chezmoi update             # git pull + apply
----

NOTE: `chezmoi update` rebases the source directory. If you have local commits there that are not pushed, the pull can stop on a conflict — `install.sh` then exits with an error rather than applying a stale state.

== Day-to-day usage

[source,shell]
----
chezmoi apply              # apply changes to $HOME
chezmoi diff               # preview changes
chezmoi add ~/.someconfig  # track a new file
chezmoi edit ~/.zshrc --apply
----
